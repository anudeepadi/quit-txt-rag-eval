Complete methods writeup for the AI-generated vs human-curated RAG comparison,

## 0. Headline, stated honestly

The original claim was "the optimized AI-generated KB reached faithfulness
parity with the human-curated KB (0.82 vs 0.77, ns)."

After correcting for the two methodological problems the reviewer raised, the
claim needs restating in two parts:

- **Faithfulness: holds, and survives correction.** On 84 questions the
  optimizer never saw, AI 0.792 vs human 0.746 (+0.046), non-inferior at
  δ=0.05 with p=0.0028.
- **Everything else: does not hold.** On answer relevancy, context precision,
  and context recall the AI KB is *worse* than human, and non-inferiority
  cannot be established. See §8.

The honest one-liner: **the AI KB hallucinates less, but retrieves worse.**

## 1. Research question and design

Can a knowledge base generated by an LLM substitute for a human-curated KB as
the retrieval corpus of a smoking-cessation RAG chatbot?

Design: two RAG systems, identical in every respect except the retrieval
corpus. Same test questions, same retriever settings, same answering model,
same prompts, same judge. Only the corpus differs. Paired by question.

Arms compared in the reported run: `ai_rag`, `human_rag`. (`web_rag` and
`baseline` exist in the harness and in earlier runs but were not in this run's
`configs_run`.)

## 4. Phase 1 — the optimization loop (where the contamination originates)

An evolutionary loop (`evo`) mutates the QA-generation prompt across
experiments. Each experiment:

1. Samples `N_SOURCE_CHUNKS = 5` source chunks from the human KB, seeded
   `RANDOM_SEED = 42` (deterministic).
2. Generates QA pairs with the candidate prompt (`gpt-4o-mini`, temp 0.3,
   max_tokens 2500, JSON mode).
3. Loads those pairs into an ephemeral ChromaDB collection (cosine).
4. **Answers `N_EVAL = 20` test questions** using that collection.
5. Scores each answer for faithfulness with an LLM-as-judge (0-10 scale
   rescaled to 0-1, `gpt-4o-mini`, temp 0.0).
6. Separately scores generated pairs on 4 quality axes (specificity,
   conversational tone, groundedness, clinical accuracy).
7. Computes a weighted combined score:

```
combined = 0.40 * rag_faithfulness
         + 0.20 * specificity
         + 0.10 * conversational_tone
         + 0.15 * groundedness
         + 0.15 * clinical_accuracy
```

8. Verdict: `KEEP if combined > best_score else DISCARD`
   (`run_data_gen_experiment.py:218-219`).

**The critical line.** `data_gen_prepare.load_test_questions` (line 92) reads
`test_set_150q.xlsx` and returns `rows[:max_rows]` with `max_rows = N_EVAL = 20`
(line 102). No flag filtering, no shuffling, no seed. **Every experiment scored
against the same first 20 questions.** Those 20 questions therefore drove:
prompt selection, per-task failure-trace analysis (the evo reviewer annotates
per-task traces), and every KEEP/DISCARD decision.

That is a development set, not a test set.

## 5. Phase 2 — final RAGAS evaluation

Both arms, identical settings (`ragas_evaluation.py`):

| Parameter | Value |
|---|---|
| Answering model | `gpt-4o-mini` |
| Temperature | 0.3 |
| Retrieval | ChromaDB, cosine, `TOP_K = 3` |
| Mode | concise (`concise_mode: true`) |
| Max tokens | 150 (concise) |
| Rate-limit sleep | 1.0s between answer calls |
| Questions | 100 |

Concise RAG prompt (verbatim):

```
You are a smoking cessation counselor.
Answer the question in 2-3 sentences using ONLY facts from the knowledge base below.
Do NOT add information, examples, or details not explicitly stated in the knowledge base.

KNOWLEDGE BASE:
{knowledge}
```

Scoring runs in an isolated subprocess worker (`_ragas_score_worker.py`) with
`RAGAS_DO_NOT_TRACK` set before import. This was necessary because RAGAS 0.4.3
wedges on Python 3.13 (`asyncio` event-loop reuse) and its telemetry blocks the
scoring loop when the analytics endpoint is unreachable.

## 6. Metrics — what each one actually measures

| Metric | Measures | Failure it catches |
|---|---|---|
| **Faithfulness** | Are the answer's claims supported by the *retrieved context*? | Hallucination |
| **Answer relevancy** | Does the answer address the *question asked*? | Evasive / off-target answers |
| **Context precision** | Are the retrieved chunks relevant? (= retrieval relevance) | Retrieving noise |
| **Context recall** | Does retrieved context cover the *ground-truth* answer? | Missing information |

Derived: `hallucination_rate = 1 − mean(faithfulness)`;
`pct_high_risk = %` of answers scoring < 0.5.

**Important:** faithfulness is measured *against retrieved context, not against
truth*. A system that retrieves poor context and then faithfully parrots it can
score high faithfulness while being unhelpful. That is why faithfulness alone
is an insufficient headline, and it is exactly what §8 shows happening.

**Not yet implemented** (reviewer point 4): answer completeness, appropriate
refusal.

## 7. Statistical methods

### 7.1 What was originally done
`statistical_tests.py` runs paired **Wilcoxon signed-rank, two-sided**
(line 163), plus Cliff's delta for effect size. Parity was inferred from a
non-significant result.

**This is invalid as an equivalence argument.** Failing to reject the null
hypothesis of "no difference" is not evidence that the difference is zero. With
SD ≈ 0.31-0.33 and n=100, the study is underpowered to detect small differences,
so "ns" was close to guaranteed regardless of truth.

### 7.2 What was added
`code/scripts/holdout_noninferiority.py` implements two paired tests on the
per-question difference `d_i = AI_i − human_i`:

**Non-inferiority (one-sided).** The appropriate test for "AI is not
meaningfully worse than human."
```
H0: mean(d) <= -δ      (AI is meaningfully worse)
H1: mean(d)  > -δ      (AI is non-inferior)
t = (mean(d) + δ) / SE,   p = P(T > t), df = n-1
```

**TOST equivalence (two one-sided tests).** Tests whether the difference lies
inside (−δ, +δ). Reported as `p = max(p_lower, p_upper)`.

**Margin.** δ = 0.05 on a [0,1] faithfulness scale, i.e. "the AI KB is not
meaningfully worse if it trails by under 5 points." **This is a placeholder and
a clinical judgment, not a statistical one — it must be agreed before final
reporting, and ideally pre-registered.** Note honestly: the non-inferiority
analysis was designed *after* seeing the data, which is itself a limitation.

NaN handling: a question is dropped only if *either* arm's score is NaN, so
comparisons stay strictly paired.

## 8. Contamination analysis and corrected results

### 8.1 Method
1. Load the 20 optimization questions exactly as the loop did: raw `rows[:20]`,
   column A, no flag filter.
2. Load the 100 evaluated questions in `q_idx` order from the per-question
   checkpoint (`checkpoint_concise_ai_rag_100.jsonl`).
3. Match on normalized text (lowercase, strip non-alphanumerics) — robust to the
   two loaders reading different paths.
4. Partition into contaminated vs held-out; recompute from the stored
   per-question scores in the result JSON. **No new API calls**, so the numbers
   are identical to what a rerun would produce.

### 8.2 Overlap
**16 of 100** evaluated questions were optimization questions (test indices
0-15). The other 4 of the 20 were among the 23 LFV-flagged rows and never
entered the RAGAS set. So **16% of the reported test set was contaminated**;
84 questions were genuinely held out.

### 8.3 Faithfulness by slice

| Slice | n | AI | Human | AI − Human |
|---|---|---|---|---|
| Full 100 (as reported) | 100 | 0.8167 | 0.7707 | +0.0460 |
| Contaminated 16 only | 16 | 0.9458 | 0.9021 | +0.0437 |
| **Held-out 84** | **84** | **0.7921** | **0.7457** | **+0.0464** |

Interpretation: the seen questions are easy — both arms score ~0.90+ on them,
versus ~0.75-0.79 on unseen ones. Their inclusion inflated **absolute** scores
by roughly 2 points. But the **paired gap is stable** (+0.044 to +0.046 across
every slice), so the AI-vs-human comparison was not itself an artifact of
contamination.

### 8.4 All four metrics, held-out, with non-inferiority (δ=0.05)

| Metric | slice | n | AI | Human | diff | NI p | non-inferior? |
|---|---|---|---|---|---|---|---|
| faithfulness | full | 100 | 0.8167 | 0.7707 | +0.0460 | 0.0011 | yes |
| faithfulness | **held-out** | 84 | 0.7921 | 0.7457 | **+0.0464** | **0.0028** | **yes** |
| answer_relevancy | full | 100 | 0.6732 | 0.6998 | −0.0266 | 0.260 | no |
| answer_relevancy | **held-out** | 84 | 0.6595 | 0.6784 | **−0.0188** | 0.231 | **no** |
| context_precision | full | 100 | 0.6108 | 0.6500 | −0.0392 | 0.364 | no |
| context_precision | **held-out** | 84 | 0.5903 | 0.6280 | **−0.0377** | 0.360 | **no** |
| context_recall | full | 100 | 0.3527 | 0.4144 | −0.0617 | 0.645 | no |
| context_recall | **held-out** | 84 | 0.3562 | 0.4175 | **−0.0614** | 0.633 | **no** |

**This is the most important table in the document.** The AI KB is non-inferior
on faithfulness only. On the three retrieval/relevance metrics it is directionally
worse, and non-inferiority fails on all three. Contamination barely moves any of
them, so the driver is metric selection, not the leak.

Mechanistic reading: `exp_0020` was optimized against a score that is 40%
faithfulness plus 60% *intrinsic pair-quality* judgments (§4). Nothing in that
objective rewards retrievability. The loop plausibly produced pairs that are
tightly self-consistent — hence faithful when retrieved — but less well matched
to the test questions, hence worse precision and recall.

Also note context recall is low for **both** arms (0.36 / 0.42). With `TOP_K=3`
over corpora of 3.5k-4.4k pairs, retrieval is probably the system's binding
constraint, independent of which corpus is used.

## 10. Threats to validity (including ones not raised)

1. **Contamination** — quantified above, 16%; corrected by the held-out split.
2. **Post-hoc test design** — the non-inferiority analysis was chosen after
   seeing results. Pre-register δ and the test before the next run.
3. **Circular KB generation** — the AI KB derives from the human KB, capping its
   ceiling and making the comparison partly self-referential (§2).
4. **Single judge model** — `gpt-4o-mini` both generates answers and judges
   them. Self-preference bias is plausible. No human validation of judge scores.
5. **Concise mode inflates faithfulness** — "use ONLY the facts provided"
   suppresses elaboration, raising faithfulness for both arms. Absolute values
   are not comparable to other papers' numbers.
6. **Unequal corpus sizes** — 3,576 vs 4,431 pairs. Retrieval difficulty differs;
   not controlled.
7. **Low context recall (~0.4) in both arms** — the retriever may dominate the
   result, muting real differences between corpora.
8. **Multiple comparisons** — four metrics × slices, no correction applied.
9. **`ebrahim_reference` rows are transcribed from a screenshot**, with n=10 and
   n=100 from a different protocol. Not directly comparable; do not put them in
   the same table as ours without a caveat.

## 11. Anticipated questions

**"Is the parity result dead?"**
No, but it is narrower. Faithfulness non-inferiority survives on clean held-out
data with the correct test (p=0.0028). The broader "the AI KB is as good as the
human KB" claim does not survive §8.4.

**"Why did removing contaminated questions barely change the gap?"**
Because contamination shifted both arms equally. The seen questions are easier,
so both scored higher on them. Paired differencing cancels shared difficulty.

**"Why does TOST equivalence fail if AI is non-inferior?"**
TOST asks whether the difference is inside ±δ. The AI advantage (+0.046) presses
against the upper bound of +0.05, so two-sided equivalence is not established.
That is a *stronger* result than parity for faithfulness, not weaker:
non-inferior and trending better.

**"Can we just declare the 150 a test set and freeze the config?"**
Not cleanly. Freezing now does not undo that 20 of them already drove selection
and failure analysis. The defensible options are the held-out 84, or a new set.

**"Why is n=84 and not 80?"**
100 evaluated minus 16 overlapping. Only 16 of the 20 optimization questions
survived LFV filtering into the evaluated set.

**"What would change the conclusion?"**
A larger, unseen test set; a δ agreed on clinical grounds; refusal-aware
scoring; and reporting all four metrics rather than faithfulness alone.
